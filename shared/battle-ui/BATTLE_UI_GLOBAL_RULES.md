# AFTER SIGNAL 전역 전투 UI 규칙

규칙 버전: `Battle UI Global 1.0`  
최초 적용 빌드: `V0.48`  
기준 전투: `P-07 무신호 감시자 V0.47`

## 1. 단일 원본 원칙

- 전투 UI의 공통 시각 규칙은 `battle/shared/V1.0/AFTERSIGNAL_BATTLE_UI_GLOBAL.css`만 수정합니다.
- 전투 UI의 공통 DOM 보정과 상태 동기화는 `battle/shared/V1.0/AFTERSIGNAL_BATTLE_UI_GLOBAL.js`만 수정합니다.
- 변경 후 `node tools/build_v048_global_battle_ui.mjs`를 실행하면 P-01, P-02, P-04, P-06, P-07과 통합본에 동일하게 반영됩니다.
- 개별 전투 HTML에 공통 CSS를 복사해 별도로 수정하는 행위를 금지합니다.
- 전역 UI 소스의 해시가 전투별 결과물에 동일하게 삽입되었는지 QA에서 검사합니다.

## 2. 전역 HUD 구성

- 상단 좌측: 자동/수동 조준·사격 전환. `A` 키와 터치·클릭을 모두 지원합니다.
- 상단 중앙: 프롤로그 좌표, 작전명, 현재 목표를 표시합니다.
- 상단 우측: 전술 AUTO. 활성화하면 자동 스킬뿐 아니라 사용 가능한 필살기도 자동 발동합니다.
- 좌측 메시지: 작고 반투명한 현장 링크 문구만 표시합니다. 전장을 크게 가리는 불투명 텍스트 박스를 금지합니다.
- 캐릭터 상태 카드: 캐릭터 위치와 가까운 화면 하단에 배치하고, 모바일 세로 화면에서는 좌·우 중단으로 이동합니다.
- 상태 카드에는 얼굴 초상화, 역할·전열, 이름, HP, 개인 보호막, 탄환 아이콘, 필살기 링만 표시합니다.
- 장탄은 숫자 문장 대신 탄환 아이콘으로 표시합니다. 재장전 중에는 탄환 슬롯과 회전 표시로 상태를 구분합니다.
- 필살기 게이지가 100%가 되면 카드의 원형 링에 밝은 보라색 그라데이션과 점멸을 적용합니다.
- 필살기 최초 설명은 P-01에서 한 번만 표시합니다. P-02 이후 반복 설명을 금지합니다.
- 자동 스킬과 필살기 발동 문구는 서로 반대쪽 구석에서 짧게 나타났다 사라지며, 중앙 불투명 박스를 사용하지 않습니다.

## 3. 인원수 대응

- 1명 전투도 허용합니다.
- 2명 이상이면 `TAB`, 숫자키, 캐릭터 카드 클릭·터치로 직접 조작 캐릭터를 변경합니다.
- 선택하지 않은 캐릭터는 자동 조준·사격합니다.
- 합류하지 않은 인물을 빈 자리나 임시 캐릭터로 채우지 않습니다.
- 파티 카드는 최대 5명까지 같은 크기 체계를 사용하고, 장탄과 필살기 표시가 캐릭터 본체를 가리지 않아야 합니다.

## 4. 전투 표현 경계

- 전역 UI 변경은 보스 기믹, 적 수, 공격력, 스킬 계수, 웨이브, 시나리오 분기와 분리합니다.
- 일반·크리티컬·코어·부위·보호막 차단 피해는 전투 코어가 제공하는 타입과 색을 유지합니다.
- 적 이름은 전장 위에 상시 표시하지 않습니다. 필요한 보스 정보만 상단 얇은 게이지에 표시합니다.
- 몹의 상시 흔들림·발광을 금지합니다. 이동 범위와 자연스러운 웨이포인트 이동으로 움직임을 표현합니다.
- 재장전 중 캐릭터는 후면 엄폐 자세로 전환하고, 사격 자세와 같은 기준 크기·바닥 앵커를 사용합니다.
- 개인 보호막은 엄폐와 피격 상태를 시각적으로 보여야 합니다. 전역 보호막이 추가되면 개인 보호막보다 먼저 소모합니다.

## 5. 반응형 가시성

- 한글 본문은 `CombatKR` 계열의 둥근 고딕을 우선하고 최소 10px 이하로 축소하지 않습니다.
- 영문 레이블은 `RelayDisplay`를 사용하며 모바일에서도 8px 이하로 축소하지 않습니다.
- 세로형 모바일에서 캐릭터 카드가 화면 하단 브라우저 UI에 가리지 않도록 중단 좌·우에 배치합니다.
- 전술 메시지, 장탄, 필살기 UI가 조준점·적 코어·캐릭터 본체를 가리지 않아야 합니다.
- Safe Area 하단 여백을 반영합니다.

## 6. 수정 및 검증 절차

1. 공통 CSS 또는 런타임 수정
2. 전역 빌드 실행
3. P-01, P-02, P-04, P-06, P-07, P-08 전투 화면 모두 생성 확인
4. 시작 버튼, AUTO 전환, 장탄 슬롯, HP·보호막, 필살기 링, 캐릭터 전환을 회귀 검사
5. 모바일 세로 360×800에서 필살기 전신·문구 가시성을, 가로 800×360에서 결과 버튼 터치와 패널 스크롤을 검사
6. 통합 HTML과 휴대용 ZIP 재생성
7. 전투별 결과와 공통 소스 해시, 첫 적 생성 후 렌더 루프 생존 여부 확인

개별 전투 수정 시에도 이 검증을 생략할 수 없습니다.

중간보스와 장별 보스의 크기·모션·등장 임팩트는 `battle/shared/BOSS_PRESENTATION_GLOBAL_RULES.md`와 `battle/shared/V1.0/AFTERSIGNAL_BOSS_PRESENTATION_GLOBAL.json`을 함께 적용합니다.

전술 AUTO의 저장·순차 발동·안전 지연·중복 종료 방지는 `battle/shared/V1.1/AUTO_ULTIMATE_GLOBAL_RULES.md`를 모든 전투에 적용합니다.

장탄·발사 간격·재장전을 포함한 무기군 피해 산정과 필살기 실제 피해 보장은 `battle/shared/V1.1/WEAPON_DAMAGE_BALANCE_GLOBAL_RULES.md`를 단일 기준으로 사용합니다.

투명 여백을 포함한 적 이미지의 표시 크기·코어·몸통·파츠 정렬과 엄폐 진입 재장전 상태 머신은 `battle/shared/V1.2/ENEMY_GEOMETRY_COVER_RELOAD_GLOBAL_RULES.md`를 모든 전투에 적용합니다. 재장전 완료 전 사격을 재개하면 잔탄이 남은 경우에만 장전을 취소하며, HUD에는 완료 전까지 실제 잔탄만 표시합니다.

V0.56 이후의 UI 직계 계층 검증·런타임 계층 복구, 전 플레이어블 캐릭터의 스탠딩 원화가 합성된 완성형 필살기 이미지 등록·사전 디코드, 일반 적 2.5D 부위 리그, 보스 안정 프레임, 모바일 회전·결과 오버레이 규칙은 `battle/shared/V1.7/COMBAT_UI_BURST_ENEMY_MOTION_GLOBAL_RULES.md`를 최우선으로 적용합니다. 기존 전투 하나라도 V1.7 공통 해시와 다르거나 완성형 컷신 등록이 누락되거나 별도 캐릭터 레이어를 다시 사용하거나 P-04 첫 적 생성 뒤 렌더 루프가 종료되면 빌드를 실패 처리합니다.

## 7. 장기 전투 진행성·모바일 자원 상한 (V0.60)

- 자동 조준은 발사 순간의 좌표만 기억하지 않고, 이동 중인 적·코어·파츠의 현재 좌표를 추적합니다. 수동 조준 탄환에는 이 보정을 강제로 적용하지 않습니다.
- 자동 스킬은 보호 기믹이 남아 있는 동안 보스 몸통이 아니라 아직 파괴되지 않은 파츠를 우선 타격합니다.
- 보스 보호 기믹은 자동 전투로도 반드시 해제 가능해야 하며, 전체 자동 전투 회귀 검사에서 실제 승리 화면까지 도달해야 합니다.
- 전투 루프는 `shots 180`, `enemyShots 96`, `particles 420`, `floaters 120`, `bossEffects 16`을 기본 모바일 상한으로 사용합니다. 상한 초과분은 오래된 객체부터 제거합니다.
- 중간보스 QA는 첫 10초 패턴 노출 검사만으로 끝내지 않습니다. 강화·무적 치트 없이 정상 파티와 정상 화력으로 시작부터 승리 또는 명시적 패배까지 실행하고, 자바스크립트 예외·무한 파츠·무한 웨이브·배열 무제한 증가가 없는지 검사합니다.
