# 전투 UI·완성형 필살기 컷신·적 모션 전역 제작 규칙 V1.7

적용 버전: AFTER SIGNAL V0.56 이후. 적용 범위: 기존 P-01/P-02/P-04/P-06/P-07/P-08 전투와 이후 제작되는 모든 일반전·중간보스전·장 보스전.

## 1. 전투 UI 단일 소스와 DOM 계층

- 모든 전투 화면은 `battle/shared/V1.7/AFTERSIGNAL_BATTLE_UI_GLOBAL.css`와 `AFTERSIGNAL_BATTLE_UI_GLOBAL.js`의 동일 해시를 사용합니다. 화면별 복사본을 임의로 수정하지 않습니다.
- `.topbar`, `.feed`, `.locks`, `.party`, `.toast`, 필살기 컷신, 시작/결과 `.overlay`는 반드시 `.viewport`의 직계 자식이어야 합니다.
- `.locks` 안에는 잠금·무결성 표시만 둘 수 있습니다. `.party`, `.unit`, `.overlay`, `.toast`를 넣는 것을 금지합니다.
- 빌드 시 위 계층을 검사해 하나라도 어기면 통합본·단독 전투 출력을 중단합니다. 런타임은 안전장치로 잘못 중첩된 전역 UI를 `.viewport` 직계 자식으로 복구하지만, 런타임 복구 통과를 빌드 성공으로 간주하지 않습니다.
- 파티 HUD는 1–5인에 같은 구조를 사용합니다. HP·개인 보호막·실제 잔탄·필살기 충전률의 클래스와 표시 우선순위는 전투별로 바꾸지 않습니다.
- 새 전투는 기존 전투 HTML을 복사해 화면별 CSS를 누적하지 않고, 공통 UI 런타임과 이 문서의 검증기를 빌드 단계에서 주입합니다.

## 2. 스탠딩 일러스트 합성형 필살기 컷신

- 모든 캐릭터의 필살기는 얼굴 크롭이나 전투 자세 이미지가 아니라 원본 스탠딩 전신 일러스트를 사용합니다. 머리·발·무기를 자르지 않습니다.
- 캐릭터 스탠딩 일러스트와 전용 효과 배경을 제작 단계에서 하나의 완성형 16:9 래스터 컷신으로 합성합니다. 런타임에서 효과 배경 위에 별도 캐릭터 이미지를 얹는 방식은 금지합니다.
- 완성형 이미지 안에서 캐릭터는 좌측 약 38–42%를 차지하고 얼굴부터 발까지 명확히 보여야 합니다. 우측에는 필살기 속성에 맞는 효과와 HTML 필살기명 표시 여백을 둡니다.
- 런타임은 완성형 이미지 1장, 회전 링 2개, 보조 궤적, 충격 플레어, 스캔 라인, 필살기명만 사용합니다. 완성형 이미지에서 캐릭터가 빠지면 빌드를 실패 처리합니다.
- 미라 보스는 청백색 릴레이 지평선·유리 신호 파편, 하늘-7은 청록색 정화 문양·데이터 플레셰트를 사용합니다. 이후 캐릭터도 진영·무기·필살기 속성에 맞는 고유 팔레트와 궤적을 가져야 합니다.
- `BURST` 단어를 사용자 표시 문구에 사용하지 않습니다. 영문 보조 표기는 `ULTIMATE SIGNAL`로 통일합니다.
- 컷신 기본 길이는 1.55초이며, 필살기 실제 피해·보호막·버프 판정은 컷신과 독립적으로 반드시 실행합니다. 컷신 ON/OFF는 시각 연출만 끄고 판정을 끄지 않습니다.
- 모바일에서도 전신 높이와 필살기명을 동시에 읽을 수 있어야 하며, 전투 HUD의 HP·조작·표적 가독성을 지속적으로 가리지 않습니다.
- 모든 필살기 컷신은 캐릭터별 전용 완성형 이미지를 사용합니다. 전투용 후면 자세나 얼굴 초상화를 확대해 대체하지 않습니다.
- 미라 보스와 하늘-7에만 한정하지 않습니다. 현재 및 앞으로 합류하는 모든 플레이어블 캐릭터는 등록 시 스탠딩 원화가 합성된 `composite`, 필살기명, 영문 보조 문구를 레지스트리에 반드시 등록합니다.
- 전투 시작 시 등록된 완성형 컷신 자산을 미리 디코드합니다. 필살기 입력 시 자산 디코드가 늦으면 최대 420ms 동안 기다린 뒤 컷신을 시작하며, 효과만 보이고 캐릭터가 비는 상태를 금지합니다.
- 플레이어블 캐릭터에 스탠딩 원화 합성형 `composite`가 없으면 별도 원화 레이어로 임시 대체하지 않고 빌드를 실패 처리합니다.
- `C · CUT-IN ON/OFF` 버튼은 모든 전투의 같은 우측 상단 위치에 존재해야 하며, 기존 마크업에 없으면 전역 런타임이 생성합니다.
- CUT-IN 상태는 `aftersignal:cutscene-enabled`에 저장하고 통합 HTML의 화면 전환 뒤에도 유지합니다. C 키와 클릭·터치는 같은 전역 설정 API를 사용합니다.

### 2.1 모바일 세로·가로 필수 조건

- 세로 화면 컷신은 완성형 이미지를 `cover`로 표시하고 캐릭터가 들어 있는 좌측 영역에 초점을 고정합니다. 전신의 세로 길이는 유지하고 가로 효과 영역만 잘라냅니다.
- 세로 화면의 필살기명과 영문 보조 문구는 화면 하단의 독립 반투명 밴드에 배치하며 전신의 얼굴과 무기를 가리지 않습니다.
- 화면 회전 또는 결과 오버레이 표시가 발생하면 진행 중 컷신을 즉시 종료하고 `aria-hidden` 상태를 복구합니다.
- 결과·시작 오버레이가 표시된 동안 해당 오버레이만 포인터/터치 입력을 소유합니다. 숨겨진 오버레이와 컷신은 입력을 가로채면 안 됩니다.
- 높이 520px 이하 가로 화면에서는 결과 패널을 내부 스크롤 가능하게 하고, 작전 종료 버튼의 최소 터치 높이를 46px 이상 유지합니다. 버튼을 뷰포트 밖으로 밀어내는 고정 높이 패널을 금지합니다.

## 3. 일반 적·인간형·동물형·드론의 자연 모션

- 한 장 이미지를 상하로 왕복시키거나 무작위로 회전·발광시키는 것을 애니메이션으로 간주하지 않습니다.
- 적 원화는 투명 불투명 합집합 크롭과 월드 히트존을 공유합니다. 이미지 크기를 바꾸면 코어·몸통·파츠 히트존과 HP 바 앵커도 함께 바꿉니다.
- 각 렌더 프레임은 60fps 시간축에서 머리/상체/하체 또는 전면/몸통/후면을 겹침 클립한 2.5D 리그로 보간합니다. 겹침 영역은 최소 2px를 두어 절단선이 보이지 않게 합니다.
- 인간형은 호흡, 이동 방향 상체 기울기, 공격 시 상체 예비 동작과 복귀를 사용합니다. 동물형은 전·후지 교대와 머리 선행을 사용합니다. 드론은 코어·핀·추진부의 서로 다른 위상을 사용합니다.
- 랜덤 이동은 월드 위치만 결정합니다. 이미지에 별도의 고주파 흔들림·발광·회전을 더하지 않습니다.
- 공격 모션은 `예비 동작 → 발사/타격 → 회복 → 이동/대기` 상태를 갖고, 피격 모션은 짧은 스케일/광량 반응 후 원래 상태로 복귀합니다.
- 동일 PNG 경로를 12/24회 반복 등록해 프레임 수가 많은 것처럼 표시하는 것을 금지합니다. 단일 원화 적은 공통 2.5D 리그를 사용하고, 전용 프레임이 있으면 실제로 다른 프레임만 상태 전환에 사용합니다.

## 4. 중간보스·장 보스

- 보스의 불투명 영역을 512px 전체 캔버스 기준으로 축소하지 않습니다. 상태별 알파 경계를 잘라 같은 바닥/중심 앵커로 정규화합니다.
- 720p 기준 중간보스 가시 몸체 높이는 약 390–430px를 목표로 하며, 전용 보호막 안쪽 지름의 86% 이상을 채웁니다. 일반 몹보다 작게 보이는 크기를 금지합니다.
- 대기 상태에서 여러 전신 이미지를 6–7fps로 무한 교차시키지 않습니다. 기준 대기 프레임은 안정적으로 유지하고 60fps 부위 리그를 적용합니다.
- 서로 다른 전신 프레임 교차는 방패 전개/파괴, 공격 충전/발사, 경직/회복처럼 의미 있는 상태 전환에서만 80–110ms 이징으로 사용합니다.
- 연사 한 발마다 보스 전신을 저해상도 `hit` 프레임으로 교체하지 않습니다. 일반 피격은 안정 기준 프레임 위의 광량·부위 스케일·히트 파티클로 표현하고, 전신 피격/경직 프레임은 강경직 상태에서만 사용합니다.
- 상태 프레임마다 하단 앵커와 코어 중심을 정규화합니다. 전환 중 보스가 순간적으로 줄어들거나 옆으로 튀는 것을 금지합니다.
- 방패 파츠와 코어 히트존, 보스 HP 바, 공격 원점은 확대된 보스 지오메트리를 따라갑니다.
- 보스 전용 동작군은 최소 12장의 동일 앵커 프레임으로 `대기/예비동작/가속/이동/감속/정착/조준/충전/발사/후속/피격/회복`을 구성합니다.
- 보스 이동은 `anticipation → acceleration → travel → braking → settle` 상태를 통과합니다. 순간이동은 전용 이탈·재진입 예고가 있는 기믹에서만 허용합니다.
- 조준·충전 뒤 `fire_release` 프레임에 도달했을 때만 투사체를 생성하며, 시작점은 현재 렌더 프레임의 코어 또는 무기 소켓과 일치해야 합니다.
- 발사 뒤 `fire_followthrough → recoil_compress → recover`를 거쳐 이동 또는 대기로 돌아갑니다. 무의미한 상하 왕복, 고주파 회전, 발광 떨림은 보스 움직임으로 사용하지 않습니다.
- 이후 제작되는 보스도 동일 상태명·바닥 앵커·코어 소켓 계약을 구현해 전역 렌더러와 QA를 재사용합니다.

## 5. 빌드 회귀 차단

- 모든 전투의 공통 CSS/JS 해시가 동일한지 검사합니다.
- 필수 UI 직계 자식, 파티 HUD 1개, 유닛 1–5개, HP/보호막/잔탄/필살기 요소를 검사합니다.
- 모든 전투의 필살기 호출이 공통 완성형 컷신 API를 사용하고, 현재 로스터 전원의 스탠딩 원화 합성형 이미지와 사전 디코드 등록이 포함됐는지 검사합니다.
- 컷신 DOM에 `.af-burst-character` 별도 캐릭터 레이어가 존재하거나 레지스트리가 `standing`과 `background`를 따로 요구하면 배포를 실패 처리합니다.
- 일반 적 렌더가 공통 적 리그를 호출하고, P-07 보스가 안정 대기 프레임·알파 크롭·확대된 노드 좌표를 사용하는지 검사합니다.
- 전역 규칙 위반 전투가 하나라도 있으면 버전 산출물과 Library 업로드를 하지 않습니다.
- P-04는 첫 적 생성 뒤 최소 3초간 렌더 루프가 계속 실행되는지 런타임으로 검사합니다. 정의되지 않은 화면별 geometry를 참조해 첫 웨이브에서 RAF가 종료되는 상태를 금지합니다.
- 모바일 QA는 세로 360×800에서 컷신 전신/문구 레이어 존재, 가로 800×360에서 결과 오버레이의 스크롤·터치 소유권·종료 버튼 활성 상태를 검사합니다.
- 모든 전투에 CUT-IN 버튼과 설정 저장 API가 있는지, OFF 상태에서도 필살기 판정이 실행되는지 검사합니다.
- 중간보스 QA는 실제 동작 자산 12장 이상, 이동 5단계, 발사 소켓 생성 시점, 프레임별 동일 크기·앵커를 검사합니다.
